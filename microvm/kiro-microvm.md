# Remote MicroVM workspace

This Kiro CLI session runs in a dedicated AWS Lambda MicroVM reached through a browser terminal.

- Only `/home/coder` persists. It is an S3 Files-backed mount scoped to this user; the system filesystem resets when the MicroVM is replaced.
- The home filesystem rejects hardlinks. Use `/opt` or `/tmp` for tools that require hardlink-capable caches; `uv` is already configured to use `/opt/uv`.
- AWS access comes from the MicroVM execution role through IMDS. Do not create or request static credentials.
- `$MICROVM_ID` identifies this workspace. The VM can suspend after idle time and terminates after its maximum lifetime, so keep durable work under `/home/coder`.
- The `workspace-web-search` MCP server provides managed AgentCore web search for current information.

This is an image-managed steering file. Add your own steering files beside it under `~/.kiro/steering/`; do not edit this file.
